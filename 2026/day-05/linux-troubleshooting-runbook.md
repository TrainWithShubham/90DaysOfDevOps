# Linux Troubleshooting Runbook – SSH Service

## Target Service

SSH Service (`ssh`)

I worked like a DevOps engineer investigating a production Linux server.
The goal was to check if the server was healthy and if the SSH service had any issue.

# 1. uname -a

Why I used it:
I first wanted to identify what Linux server I was working on.

How it works:
This command shows Linux kernel version, architecture, and operating system details.

What I observed:
The server was running Ubuntu Linux on AWS EC2 with x86_64 architecture.

Debugging mindset:
Before troubleshooting any issue, DevOps engineers first identify the environment and server details.

# 2. cat /etc/os-release

Why I used it:
To check the Ubuntu operating system version.

How it works:
This file stores Linux distribution information.

What I observed:
The server was running Ubuntu 26.04 LTS.

Debugging mindset:
Different Linux versions may behave differently, so checking OS version is important.

# 3. mkdir /tmp/runbook-demo

Why I used it:
To verify the filesystem was working correctly.

How it works:
This command creates a temporary folder.

What I observed:
The folder was created successfully.

Debugging mindset:
If the filesystem is damaged or read-only, applications may fail to create files.

# 4. cp /etc/hosts /tmp/runbook-demo/hosts-copy && ls -l /tmp/runbook-demo

Why I used it:
To test file copying and permissions.

How it works:
The command copies a system file into the temporary folder and lists the files.

What I observed:
The file copied successfully and permissions looked normal.

Debugging mindset:
This confirms the server can read and write files correctly.

# 5. top

Why I used it:
To monitor CPU and memory usage in real time.

How it works:
This command shows running processes and system resource usage.

What I observed:
CPU usage was very low and the server was healthy.

Debugging mindset:
If CPU usage becomes very high, applications and services may slow down or crash.

---

# 6. free -h

Why I used it:
To check RAM and memory usage.

How it works:
This command displays total, used, and available memory.

What I observed:
The server was using low memory and had enough available RAM.

Debugging mindset:
Low available memory may cause slowness or application failures.

# 7. df -h

Why I used it:
To check disk usage and free storage space.

How it works:
This command displays mounted disks and their usage.

What I observed:
Only 13% of the root filesystem was used.

Debugging mindset:
If disk becomes full, logs, applications, and services may stop working.

---

# 8. du -sh /var/log

Why I used it:
To check how much disk space logs were using.

How it works:
This command calculates folder size.

What I observed:
Log folder size was normal.

Debugging mindset:
Large logs can consume all disk space and cause server problems.

# 9. ss -tulpn

Why I used it:
To check listening ports and active services.

How it works:
This command shows network ports and processes using them.

What I observed:
SSH service was listening on port 22.

Debugging mindset:
If SSH is not listening on port 22, remote login will fail.

# 10. ping google.com

Why I used it:
To verify network and internet connectivity.

How it works:
This command sends packets to another server and waits for reply.

What I observed:
The server successfully reached Google.

Debugging mindset:
If ping fails, the server may have network or DNS issues.

# 11. journalctl -u ssh -n 50

Why I used it:
To review recent SSH service logs.

How it works:
This command reads logs generated by the SSH service.

What I observed:
I noticed multiple failed login attempts and invalid users from public IP addresses. I also saw my successful public key login.

Debugging mindset:
Logs provide the most important clues during troubleshooting.

# 12. tail -n 50 /var/log/auth.log

Why I used it:
To review authentication and login activity.

How it works:
This command shows the last 50 lines of the authentication log file.

What I observed:
The logs showed SSH login attempts, authentication failures, and successful sessions.

Debugging mindset:
Authentication logs help detect login issues and suspicious access attempts.
