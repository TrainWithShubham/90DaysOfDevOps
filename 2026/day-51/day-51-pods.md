Day 51 – My First Kubernetes Pod
Objective

Today I learned how to create and manage my first Pod in Kubernetes using a YAML manifest.

What is a Pod?

A Pod is the smallest unit in Kubernetes. It can contain one or more containers. Usually, one Pod runs one application container.

Example:

One Pod → One Nginx container

What is a Manifest?

A manifest is a YAML file that tells Kubernetes what resource to create and how it should be configured.

Kubernetes reads the YAML file and creates the resource.

Main Parts of a Pod Manifest
apiVersion

It tells Kubernetes which API version is used for the resource.

Example:

apiVersion: v1

Pods use v1.

kind

It tells Kubernetes what resource to create.

Example:

kind: Pod

metadata

Metadata gives information about the resource such as its name and labels.

Example:

Name: nginx-pod
Label: app=nginx

Labels help organize and identify Kubernetes resources.

spec

The spec section describes the desired state of the Pod.

Inside spec, we define:

Container name
Docker image
Container port

The containers field must always be inside the spec section.

apiVersion: v1
kind: Pod

metadata:
name: nginx-pod
labels:
app: nginx

spec:
containers: - name: nginx
image: nginx:latest
ports: - containerPort: 80

# Error I Faced

I received the following error:

"unknown field 'containers'"

Reason:

The containers section was not inside the spec section because of incorrect YAML indentation.

The API Server validates every manifest before creating resources.

Since the YAML structure was incorrect, the API Server rejected the request.

After fixing the indentation, the Pod was created successfully.

# Pod Creation Flow

kubectl sends the YAML file to the API Server.
The API Server validates the manifest.
The Pod information is stored in etcd.
The Scheduler selects a node.
The kubelet receives the request.
The container runtime downloads the image if needed.
The container starts.
The Pod status becomes Running.

# What I Learned from Logs

kubectl logs displays the output generated by the application running inside the container.

It is mainly used for troubleshooting and debugging applications.

# What I Learned from kubectl exec

kubectl exec allows us to enter a running container and execute commands.

Inside the nginx container, I verified:

Current working directory
Files and folders
Installed Nginx version

# Pod Deletion

After deleting the Pod, it was not recreated automatically.

Reason:

The Pod was created directly from a Pod manifest.

There was no Deployment or ReplicaSet managing the Pod.

Only Deployments and ReplicaSets automatically recreate Pods.
